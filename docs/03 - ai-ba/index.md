# 业务分析

## 新应用

### 我们给出一写非标准化的做法，一个新的应用可以是：

1. 一个模糊的想法， 我们称之为 idea ；
2. 然后对这个想法进行头脑风暴并形成文字作为业务需求的起点，我们称之为 BRD ;
3. 然后产品经理基于用户需求做出分析，请要求技术团队做出初步的分析和架构设计（含假设）, 我们称之为 PRD ，或者称之为 FDD （功能设计文档）; 在 brd  中需要给出用户故事地图和given-when-then 的验收条件
4. 在现在 AI 的年代，可以快速给出原型设计，供用户和产品经理参考。这个时候，可以是应用架构师使用领域驱动设计和用户、产品经理一起理清概念，划分业务域。
5. 用户和产品经理看到原型后， 有了新的想法或者修正了之前的看法。

## 关于业务需求文档

除了上面提到的 idea，brd, prd, tdd 和 adr, 我们一般还需要提供：

1. 原来的流程
2. 采用这个应用之后的流程
3. 以及使用这个系统的角色及其操作权限
