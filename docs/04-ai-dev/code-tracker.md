# Code Tracker

Code Tracker 可以理解为一类用于追踪代码变化、调用关系和影响范围的工具。它把提交、文件、符号、调用方、测试和发布记录连接起来，帮助开发者和 AI Agent 回答“这段代码从哪里来、被谁使用、改动会影响什么”。

## 主要追踪对象

- Git commit、branch、tag 和 Pull Request
- 文件、类、函数、接口和配置项
- 定义、引用、调用方和被调用方
- 测试用例与被测代码的关系
- 代码所有者、审查记录和变更历史
- 构建、部署和生产错误与代码版本的关系

## 典型问题

- 这个函数最近为什么被修改？
- 这个公共接口有哪些调用方？
- 修改一个类型会影响哪些模块和测试？
- 某次生产错误对应哪个 commit？
- 一个功能从需求到代码、测试和发布是否完整？
- 哪些代码长期没有测试或审查？

## 与普通 Git Log 的区别

`git log` 主要展示提交历史；Code Tracker 进一步建立“提交、代码符号、调用关系、测试和发布”的关联。它通常结合 Git 数据、语言解析器、代码索引、CI 记录和 Issue/PR 元数据使用。

## AI Agent 中的用法

Code Tracker 可以作为 Agent 的上下文工具：

1. Agent 识别要修改的文件或符号。
2. Tracker 查询定义、引用和历史变更。
3. Agent 评估影响范围并读取相关测试。
4. 修改完成后，Tracker 关联新的 diff、测试结果和 Review。
5. 后续 Agent 根据完整记录继续工作。

这比只把当前文件交给模型更可靠，因为它同时提供代码语义、变更历史和协作上下文。

## 建设建议

- 使用 commit SHA、符号全限定名和文件路径作为稳定锚点。
- 区分代码事实、人工决策和模型推断。
- 为每条关系记录来源、时间和版本。
- 支持增量索引，避免每次扫描整个仓库。
- 对分支、生成代码、重命名和代码移动做好去重处理。
- 让用户可以从图谱结果跳回源码、commit 或测试。

## 局限

静态关系无法完整表达反射、动态派发、代码生成和运行时配置。代码历史也不能自动说明业务意图，因此 Code Tracker 的结果应作为调查线索和影响分析依据，不能替代测试、领域判断和人工 Review。
