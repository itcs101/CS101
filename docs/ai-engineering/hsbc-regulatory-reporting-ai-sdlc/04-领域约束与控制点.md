# 04 领域约束与控制点

以下控制点来自仓库已有的监管报送研究资料，用于设计检查清单，不构成法律意见。正式实施前必须由对应市场的监管合规、数据保护和信息安全负责人核验。

## 1. 报送分类

| 层级 | 必填内容 | 控制问题 |
| --- | --- | --- |
| L1 | 监管大类 | 是否属于资本流动性、交易明细、跨境外汇、AML/税务或本地专项？ |
| L2 | 监管子类 | 是否使用集团统一字段和规则分类？ |
| L3 | 监管机构 | 路由、权限和审批主体是否正确？ |
| L4 | 官方报表编号/模板名 | 是否记录版本、发布日期和生效日期？ |
| L5 | 报送频率 | 调度、截止时间和补报规则是否可验证？ |

## 2. 数据驻留

| 类别 | 默认设计 | 必须证明 |
| --- | --- | --- |
| 强制本地存储 | 原始数据、计算和留存均在属地 | 本地部署、访问控制、备份和监管调取能力 |
| 本地副本 | 境外系统不得替代属地完整副本 | 副本完整性、同步延迟和属地优先调取 |
| 自由流转 | 仍按数据分类和最小化原则传输 | 跨境审批、传输字段、加密和接收方 |
| 待确认 | 禁止上线 | 合规负责人书面决定 |

默认禁止原始客户、交易、AML 和 Token Vault 数据进入 Jira、Git、AI 会话或跨境日志。跨境只允许经过批准的汇总或不可逆脱敏结果。

## 3. 控制点清单

- 监管来源具备权威链接、发布日期、适用市场和复审日期。
- 数据字段有分类、来源、责任人、留存要求和访问角色。
- 数据血缘覆盖源系统、转换规则、报表字段和提交回执。
- 规则变更具备双人复核和回归测试。
- 关键报表具备重算、差异比较、人工放行和回滚能力。
- 操作日志、审批日志和报送回执不可被普通开发权限删除或修改。
- 数据质量规则覆盖完整性、准确性、及时性、一致性和重复性。
- 监管问询可以在约定时限内提供字段、规则、批次和审批的溯源证明。
- 任何例外都具备失效日期，不得永久豁免。

## 4. AI 使用控制

AI 只能处理最小必要的脱敏上下文。模型输出不得直接成为监管解释或生产规则；必须经过业务、合规和技术责任人复核。模型、Prompt、Skill 和 Hook 的版本要进入变更记录。
