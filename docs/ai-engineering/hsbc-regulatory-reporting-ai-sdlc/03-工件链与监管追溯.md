# 03 工件链与监管追溯

## 1. 工件清单

| 工件 | 产生阶段 | 最小内容 | 下一阶段读取 |
| --- | --- | --- | --- |
| `intent.md` | 计划 | 问题、结果、用户、范围和未决问题 | `spec.md` |
| `spec.md` | 设计 | 需求、业务流程、控制目标和风险 | `plan.md` |
| `plan.md` | 构建准备 | 文件、顺序、测试、风险和回滚 | 代码与测试 |
| 验收证据 | 测试 | 测试结果、数据质量、截图或证据哈希 | PR |
| `review.md` | 部署 | 缺陷、安全、合规和计划一致性结论 | 发布审批 |
| `change-record.md` | 维护 | 变更原因、影响、审批和回滚 | 下一轮 `intent.md` |

## 2. 统一标识

```text
REQ-<market>-<year>-<number>       监管或业务需求
SPEC-<REQ-ID>-<version>            需求与设计
PLAN-<REQ-ID>-<version>            实施计划
EVD-<REQ-ID>-<test-run>            验收证据
CHG-<REQ-ID>-<version>             生产变更
```

每个标识都必须关联 Jira Key、Git commit SHA、作者、审批人和创建时间。

## 3. 追溯矩阵

最小追溯链为：

```text
监管来源
  → L1/L2/L3/L4/L5
  → REQ-ID / Jira Epic
  → Capability / Story
  → 字段与规则
  → 数据源和报送报文
  → 测试用例
  → 验收证据
  → PR / 发布版本
```

每条链都必须能正向回答“这条监管要求实现在哪里”，也能反向回答“这个字段为什么存在”。缺失任一环节时，Story 不能进入 `Release Approval`。

## 4. 证据要求

- 证据保存位置必须是受控系统，Git 只保存摘要、链接和哈希。
- 测试结果必须包含测试数据分类、运行环境、规则版本和时间戳。
- 生产报送证据必须记录报送批次、报表版本、数据快照标识和提交回执；不保存原始敏感载荷。
- 驳回、例外和豁免必须记录理由、期限、批准人和复审日期。

## 5. 变更传播

监管来源更新时，`regulatory-intake` 生成影响分析。受影响的 `spec.md`、Story、规则、测试和控制点必须重新评审；未受影响的部分也要留下“已分析、无需变更”的证据。
