# 06 实施路线图与验收指标

## 1. 分阶段路线

| 阶段 | 工作 | 退出条件 | 回滚方式 |
| --- | --- | --- | --- |
| 0 治理确认 | 确认数据分类、Jira 权限、模型区域、法规负责人 | 决策记录获批准 | 回到人工流程 |
| 1 模板试运行 | 用历史脱敏案例填写全部工件 | 业务、合规、技术三方评审通过 | 删除试验项目，不影响生产 |
| 2 最小闭环 | 选择一个市场、报表编号和数据链路 | 能完成需求到验收证据追溯 | 停用自动化，保留人工报送 |
| 3 Jira/MCP 集成 | 同步状态、Key、SHA 和审批 | 双系统冲突能自动阻断 | 关闭写入，仅保留只读 |
| 4 控制自动化 | 上线 Hook、CI、PR 检查 | 阻断敏感数据和无审批发布 | 恢复上一版配置 |
| 5 扩展 | 复制到其他市场和报表族 | 每个市场有本地控制负责人 | 按市场独立暂停 |

## 2. 验收场景

1. 新增监管来源能生成带来源和未决问题的 `intent.md`。
2. 缺少 L1-L5、jurisdiction 或报表编号时，Jira Story 不能进入 `Compliance Review`。
3. 需求包含原始客户数据时，Skill 报告阻断，Hook 或 CI 拒绝提交。
4. 追溯矩阵缺少字段到报表的链路时，PR 检查失败。
5. 生产发布没有发布经理授权时，部署命令被 Hook 阻止。
6. 运行指标突破阈值时，只能生成诊断或受审查的回滚 PR。
7. 任一变更都能从 Jira Key 定位到工件、PR、测试证据和发布记录。

## 3. 指标

| 指标 | 目标方向 | 数据来源 |
| --- | --- | --- |
| 需求从来源到 `intent.md` 的时间 | 缩短 | Git 历史 |
| 首轮合规评审通过率 | 提高 | Jira |
| 需求返工次数 | 降低 | Jira/Git |
| 报表规则适配周期 | 缩短 | Jira |
| 追溯证明准备时间 | 满足项目约定 | 证据库 |
| 数据质量缺陷逃逸数 | 降低 | 运行监控 |
| 敏感数据进入 Jira/Git/AI 的事件数 | 必须为零 | DLP、CI、审计日志 |
| 未授权生产操作数 | 必须为零 | Hook、平台日志 |

## 4. 责任分工

业务负责人负责意图和报送目标；BA 负责需求与用户故事；合规负责人负责监管解释；数据负责人负责驻留和血缘；架构师负责方案；QA 负责证据；安全团队负责平台控制；发布经理负责生产门；服务负责人负责运行闭环。
