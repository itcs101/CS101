# 05 Skill 策略与推荐清单

## 1. 选择原则

优先复用维护活跃、许可证清晰、权限边界可控的通用能力。涉及监管解释、属地化判断和报送血缘的能力自行设计，由合规负责人维护。任何开源 Skill 引入前必须完成来源、许可证、依赖、更新策略、网络访问和敏感数据处理审查。

Skill 是建议性控制，不是审批机制。不可违反的要求必须由 Hook、CI、PR 检查、权限或人工审批强制执行。

## 2. 推荐能力

| 能力 | 建议 | 说明 |
| --- | --- | --- |
| 文档与 Markdown 检查 | 复用通用工具 | 检查标题、链接、表格和 front matter |
| Git 工件关联 | 自研轻量脚本 | 验证 Jira Key、工件 ID 和 commit SHA |
| Jira MCP | 采用组织批准的连接器 | 只开放必要的 Issue、评论和状态操作 |
| PR 审查 | 复用组织标准能力 | 增加监管追溯和数据边界检查 |
| 测试证据收集 | 自研项目适配器 | 生成脱敏摘要和证据哈希 |
| 监管需求摄取 | 自研 | 将受控来源转成 `intent.md`，不得自行作法律结论 |
| 数据属地化检查 | 自研 | 判断字段、处理位置和跨境载荷是否完整 |
| 报送血缘检查 | 自研 | 检查源字段到报表字段的可追溯性 |

## 3. 首批自研 Skill

| Skill | 触发时机 | 输出 |
| --- | --- | --- |
| `regulatory-intake` | 新法规、监管问询或变更通知 | `intent.md`、影响范围、待确认问题 |
| `jira-requirement-review` | 创建或修改 Epic/Story | 缺失字段、层级和验收标准报告 |
| `regulatory-data-localization-review` | 变更数据源、字段、部署或跨境接口 | 属地化检查表和阻断项 |
| `reporting-lineage-review` | 新增/修改报表字段和规则 | 追溯矩阵缺口报告 |
| `plan-compliance-review` | `plan.md` 提交或 PR 创建 | 计划与控制目标、测试和回滚的一致性报告 |

详细设计见 `skill-designs/`。稳定后再部署到目标项目的 `.claude/skills/<name>/SKILL.md`。

## 4. 确定性控制

- Hook：阻止读取敏感路径、阻止生产命令和阻止修改冻结文件。
- CI：检查工件字段、Jira Key、追溯矩阵、敏感信息扫描和测试结果。
- PR：检查分支保护、审批角色、法规来源和发布证据。
- 平台权限：限制 MCP 工具、模型区域、网络域名和生产凭据。
